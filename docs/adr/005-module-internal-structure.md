# ADR-005: Внутренняя структура модулей («модульность внутри модульности»)

**Статус:** Принято · **Дата:** 2026-08-22 · **Место решения:** архитектурный чат

## Контекст

Модули изолированы схемами БД, манифестами и событиями (ADR-001/002).
Требование: изоляция и **внутри** модуля — точечное обновление/замена одной
части модуля не должно ломать слабо связанные части. Python не заставляет
писать всё классами; управляем связностью границами и контрактами, а не
парадигмой ради парадигмы.

## Решение

### 1. Слои внутри модуля (направление зависимостей строго вниз)

```
router.py  — HTTP: валидация, роли, вызов service. Бизнес-логики нет.
service.py — бизнес-логика и правила. Не знает про HTTP. Тестируется без API.
models.py  — ORM-модели схемы модуля.
manifest.py— регистрация в ядре. tasks.py — фоновые задачи (если есть).
```

- `router` не обращается к `models` напрямую — только через `service`.
- `service` не импортирует `router`; `models` не импортируют `service`.

### 2. Где классы обязательны, где функции

**Классы (и интерфейсы/ABC)** — для всего, что является точкой расширения
или имеет состояние/полиморфизм:
- стратегии и адаптеры: `BaseConnector` (ABC) и наследники — эталон;
- реестры и фабрики: `ConnectorRegistry`;
- доменные исключения: `AccountingError` (тип ошибки = ветка обработки);
- любые компоненты с конфигурацией/жизненным циклом.

**Функции** — для бизнес-логики и расчётов без состояния (проведение
документа, отчёты): тривиально тестируются, не несут скрытых зависимостей.

Правило не «всё классами», а: **новая точка расширения = новый ABC/интерфейс
в контракте модуля**. Хочешь добавить способ интеграции — наследуй
`BaseConnector`, не трогая чужой код.

### 3. Изоляция фич внутри растущего модуля

- Пока модуль мал — один набор слоёв (2–5 файлов).
- При росте делится на подпакеты по фичам (`features/<name>/...` со своими
  слоями). Связи между фичами одного модуля — через события шины или
  публичные service-функции фичи-поставщика; **циклические импорты
  запрещены**, нарушение — блокирующее на ревью.
- Общее для фич (модели-справочники, утилиты) — в явной общей части модуля.

### 4. Внедрение зависимостей

Через FastAPI `Depends` (сессия БД, текущий пользователь, настройки) —
слои не создают зависимости сами, тестируются с подстановками.

## Следствия

- Точечные изменения локализованы: правка одной фичи не требует правок
  в соседних; проверяется на ревью по направлению импортов.
- Service-слои покрываются юнит-тестами без HTTP (уже так в
  mgmt_accounting — паттерн закреплён как стандарт).
- Новый модуль начинается со стандартного набора файлов и копирует
  эталонную структуру (учёт — референс; connectors — эталон ABC).
