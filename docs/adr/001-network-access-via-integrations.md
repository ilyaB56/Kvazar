# ADR-001: Доступ к сети — только через интеграционный модуль

**Статус:** Принято · **Дата:** 2026-08-18 · **Место решения:** архитектурный чат

## Контекст

Система — модульный монолит (ядро + подключаемые модули) с планом разделения
на «локальное приложение у клиента + облачный интеграционный хаб». Клиенты —
МСБ, включая недоверчивых к облакам; критичны оффлайн-работоспособность и
прозрачность («куда уходят мои данные»).

Альтернатива «дать каждому модулю свои настройки сети» отклонена: она создаёт
множество точек аудита, размазывает секреты по системе, ничего не даёт клиенту
(его волнуют адреса назначения, а не модули) и ломает будущее разделение
локальный контур / хаб.

## Решение

Единственный модуль с правом сетевого взаимодействия — **интеграционная
платформа** (`src/modules/integrations`), а именно слой коннекторов
(`connectors/`) и, в будущем, мост `hub_link`.

- Весь **исходящий** трафик — только через коннекторы (HTTPS).
- Весь **входящий** трафик — только через webhook-эндпоинты интеграционного
  модуля или облачный хаб (который доставляет события локальной части по
  инициативе клиента — pull/push-мост, работает за NAT).
- Бизнес-модули (учёт, CRM, ИИ и др.) **не открывают сетевых соединений
  никогда**; внешний мир приходит к ним в виде событий шины
  (`webhook.received.*`, `integration.data.fetched` и т.п.).

Инфраструктурные исключения (не бизнес-модули, реализуются компонентами ядра):
обновления (модель pull, подписанные пакеты), проверка лицензии (офлайн,
проверка подписи ключа Ed25519, без «звонков домой»), телеметрия ошибок
(opt-in, выключена по умолчанию), облачный бэкап (opt-in, S3-совместимое
хранилище, выключен по умолчанию). Фронтенд — без внешних CDN, все ассеты
самохостинг.

## Правила (обязательные)

1. Импорт сетевых библиотек (`httpx`, `requests`, `urllib.request`, `aiohttp`,
   `socket` и аналогов) разрешён **только** в `src/modules/integrations/connectors/`
   (плюс `hub_link`, когда появится). Enforced линтером (banned-api) и ревью.
2. Секреты внешних систем хранятся только в подключениях (`connections`,
   Fernet-шифрование). Ключи в бизнес-модулях запрещены.
3. Единая точка выхода: белый список доменов (allowlist), журнал каждого
   обращения (домен, время, статус, объём), лимиты частоты. В строгом режиме
   новый домен запрещён, пока не разрешён явно.
4. Модули включаются/выключаются целиком (`module_registry.is_active`);
   отдельных сетевых настроек у модулей нет.
5. Оффлайн-профиль (ноль активных подключений) — полная работоспособность
   ядра, учёта, CRM и локального ИИ (Ollama).
6. Внешние LLM (если понадобятся вместо локального Ollama) — тоже через
   коннектор, исключений не создаём.

## Следствия

- Аудит сетевой активности в одном месте; сильное ИБ-позиционирование
  («наружу ходит только один шлюз с журналом»).
- Разделение «локальное приложение + облачный хаб» не потребует изменений
  в бизнес-модулях — наружу ходят только события.
- Первые задачи разработки: линтер-запрет сетевых импортов вне коннекторов
  и перенос API на `/api/v1` (см. ADR-002).
