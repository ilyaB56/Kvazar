## 1. Контекст и проблема

Коробка v1 (box-installer-spec, полевой тест пройден 2026-10-04) — это
Docker-стек с проектом `kvazar` и веб-интерфейсом nginx на
`http://localhost:8080`. Сегодня точка входа пользователя — **ярлык,
открывающий браузер** (`deploy/installer/kvazar-setup.iss:16,64-68`:
`AppURL = http://localhost:8080`, ярлыки десктопа/Пуска ведут на URL).
Сотрудники ходят по LAN-адресу `http://<IP-сервера>:8080` в браузере.

Боли (сформулированы владельцем, реестр 2026-09-16/19):

- «Прям приложение»: ERP живёт в вкладке среди прочих вкладок, без
  собственной иконки в панели задач, без трея, без нативных уведомлений
  Windows — для сотрудников МСБ это «сайт», а не «рабочая программа».
- Адрес сервера приходится запоминать/записывать; на каждой новой
  машине сотрудника это ритуал «откройте браузер и введите IP».
- Уведомления видны только внутри открытого окна (центр уведомлений
  v1-lite — клиентский, `frontend/src/layouts/NotificationCenter.vue`);
  свернул окно — узнал об упавшей синхронизации завтра.
- Включать ПК → открывать браузер → вводить адрес → логин — каждый день.

Решение владельца (канон, не пересматривается этой спекой):
**v1.1 = Tauri-оболочка для ВСЕХ пользователей** — лёгкий (~5 МБ)
нативный клиент, внутри которого тот же веб-интерфейс с сервера
(паттерн Slack/Discord/Notion; реестр 2026-09-16). Оболочка должна
уметь адрес как локального сервера (LAN-IP), так и будущего
hub_link-моста (`https://компания.kvazar.ru`, реестр 2026-09-19, этап C
того плана — «настройка адреса моста в Tauri-клиенте»).

Граница версии: оболочка — это **обёртка НАД существующим веб-интерфейсом,
не форк фронта**. Фронтенд не меняется (допускается точечная адаптация по
query-признаку `shell=tauri`, §13). Веб-интерфейс в браузере остаётся
полноценным способом работы — оболочка опциональна.

## 2. Термины

- **Оболочка (shell)** — нативное приложение Windows на Tauri 2, которое
  открывает веб-интерфейс Квазара в собственном окне (WebView2) и
  добавляет трей/уведомления/автозапуск. Не содержит бизнес-логики ERP.
- **Адрес сервера (server_url)** — базовый URL коробки
  (`http://localhost:8080`, `http://192.168.1.10:8080` или будущий
  `https://компания.kvazar.ru`). Единственный пользовательский параметр
  первого запуска.
- **Экран-заглушка (unavailable screen)** — локальный экран оболочки
  «Квазар не запущен», показываемый вместо ошибки webview при
  недоступном сервере.
- **Экраны оболочки** — три локальных экрана (настройка адреса,
  «не запущен», «подключаемся»), статический HTML в бандле оболочки;
  не являются частью фронтенда ERP.
- **Тост** — нативное уведомление Windows (центр уведомлений ОС)
  через tauri-plugin-notification.
- **hub_link** — планируемый мост «локальная коробка ↔ облачный хаб»
  (реестр 2026-09-19); для этой спеки — просто «любой https-адрес».
- Используются существующие термины проекта: коробка, стек, health
  (`/health`), визитка kvazar-download, kvazar-setup, WEB_PORT, LAN-IP.

## 3. As-is (ссылки на код)

- **Коробочный стек**: `docker-compose.box.yml` — проект `kvazar`;
  web-прокси (nginx) публикует `${WEB_PORT:-8080}:80` на 0.0.0.0
  (строки 103–112, комментарий: LAN-доступ сотрудника); API наружу не
  публикуется (`127.0.0.1:8000`, строка 70). WEB_TLS=1 — HTTPS-режим
  с self-signed сертификатами (`docker-compose.yml:100-104`).
- **Health**: единственный канонический эндпоинт `GET /health` — корень
  приложения (`src/main.py:38-40`, возвращает `{"status": "ok"}`),
  nginx проксирует точным `location = /health`
  (`frontend/nginx.conf:54-58`). `/api/v1/health` НЕ существует — урок
  реестра 2026-10-04 («health-URL — один канонический на систему»).
  `GET /api/v1/modules` — реестр модулей (`src/main.py:43-51`) —
  характерный «отпечаток Квазара» (для отличения от чужого сервиса на
  том же порту, см. О3).
- **Точка входа сегодня**: ярлыки установщика ведут на URL
  (`kvazar-setup.iss:64-68`) — открывается браузер по умолчанию.
  Адрес LAN показывается установщиком при завершении (бокс-спека §3.9).
- **Бренд**: продукт «Квазар» кириллицей (решение 2026-09-03);
  латиницей — **Kvazar с K** (решение основателя 2026-09-26: файлы
  `kvazar-*.cmd/iss`, образы `ghcr.io/ilyab56/kvazar-*`). Знак/иконка —
  QuasarMark (`docs/design/mockup/brand/`, violet-базовая).
- **Фронтенд**: Vue 3.5 + Vite 6 + TS, собственный UI-кит на Tailwind 4
  (`frontend/package.json`), i18n ru/en. SPA отдаётся nginx с
  `Cache-Control: no-cache` для index.html и immutable для ассетов
  (`frontend/nginx.conf:60-71`). API ходит через тот же origin
  (`location /api/`), CORS не нужен (`nginx.conf:33-40`).
- **Сессия — НЕ куки**: JWT Bearer; access/refresh токены фронт держит
  в localStorage (`frontend/src/stores/auth.ts:9-10`:
  `erp.access_token` / `erp.refresh_token`; persist при «запомнить» —
  строки 102–113; api-client добавляет `Authorization`, 401 → refresh →
  повтор, `frontend/src/api/client.ts:17-22,27-41`). Storage вебвью
  привязан к origin — это и есть «сессия как в браузере».
- **Уведомления сегодня**: центр уведомлений v1-lite — клиентский,
  источники sync-errors/бэкапы/ИИ-предложения, поллинг раз в 60 с,
  прочитанность в localStorage (`NotificationCenter.vue:88-191`).
  Серверных уведомлений нет (бэклог H п.2, реестр 2026-09-26: спека
  серверных уведомлений пишется параллельно; эндпоинта `/notifications`
  в `src/` нет). Оболочка обязана предоставить МЕХАНИЗМ тостов, не
  дублируя клиентскую логику (§8).
- **Браузерозависимые места фронта** (кандидаты адаптации, §13):
  blob-скачивания через `URL.createObjectURL` + `link.download`
  (`AssistantView.vue:133-144`, `ReportsView.vue:147-150`,
  `ToolsView.vue:252-255`); печать `window.print()` карточки сделки
  (`CrmView.vue:296`). Кнопок «открыть в браузере» и `window.open` во
  фронте НЕТ (grep пуст).
- **Дистрибуция**: CI `.github/workflows/release-images.yml` — образы в
  GHCR + зеркала base-образов + `installer`-джоба (windows-latest, ISCC,
  артефакт + приложение к GitHub Release на тегах) — готовый образец
  для джобы оболочки. Открытая раздача — публичный репозиторий-визитка
  **github.com/ilyaB56/kvazar-download** (Release v1.0.0-beta с
  `kvazar-setup.exe`; операционка: новый тег + замена ассета; реестр,
  2026-10-04). Установщик коробки — Inno Setup 6, per-user
  (`PrivilegesRequired=lowest`), фаза стека на `ssPostInstall` после
  `WaitForHealth` (`kvazar-setup.iss:584-604`).
- **Чего нет**: никакого нативного клиента, ни конфига адреса, ни
  трея/уведомлений ОС. Все состояния «сервер не запущен» сегодня —
  ошибка браузера (ERR_CONNECTION_REFUSED).

## 4. To-be: архитектура и принципы

**Tauri 2** (Rust core + системный WebView2 на Windows; без движка
Chromium в бандле — размер ~5 МБ). Оболочка — отдельный Rust-крейт
`shell/` в корне репозитория (не в `frontend/`), собирается независимо
от стека и фронта.

Инварианты (обязательные для всех этапов):

1. **Обёртка, не форк**: главное окно загружает настраиваемый
   `server_url` (loadUrl). Ни одного экрана ERP внутри оболочки не
   рисуется; вся бизнес-логика — на сервере и в существующем фронте.
2. **Никаких node-зависимостей в рантайме**: экраны оболочки —
   статический HTML+CSS+vanilla JS в бандле крейта; фронтенд ERP
   (Vue/Vite/node) в сборке оболочки не участвует.
3. **IPC-изоляция**: загруженный удалённый контент НЕ получает доступа
   к Tauri API (в Tauri 2 доступ удалённых origin к IPC по умолчанию
   закрыт; capabilities оболочки — только для локальных экранов).
   Фронт ERP не знает об оболочке, кроме query-признака (§13).
4. **Адрес — только http(s)**: схема `http`/`https`, иначе отказ с
   сообщением (§5.2). Токены/пароли оболочка НЕ принимает и не хранит
   (§11).
5. **Здоровье по канону**: любая проверка сервера — `GET /health`
   (+зонд принадлежности, §5.4). Никаких новых health-эндпоинтов.
6. **Один канонический бренд**: окно/процесс/установщик — «Квазар»
   (латиница Kvazar в именах файлов/идентификаторах, §12).

Состав оболочки (плагины Tauri 2, официальные,
[plugins-workspace](https://github.com/tauri-apps/plugins-workspace)):

| Функция | Механизм | Этап |
|---|---|---|
| Одноэкземплярность | tauri-plugin-single-instance | A |
| Трей (иконка, меню) | ядро Tauri 2 (tray-icon feature) | A |
| Автозапуск с Windows | tauri-plugin-autostart | B |
| Нативные тосты | tauri-plugin-notification | B |
| Окно/адрес/состояния/конфиг | Rust-код крейта + статические экраны | A/B |

Роли пользователей (владелец / сотрудник / удалённый сотрудник) для
оболочки одинаковы: разница только в значении `server_url`
(localhost / LAN-IP / будущий hub_link-адрес) — тот же бинарник, та же
установка.

## 5. Первый запуск и адрес сервера

### 5.1 Экран первого запуска

Показывается, когда конфиг пуст (первая установка) или по команде
«Настройки» (§7). Элементы:

- поле «Адрес сервера Квазара», дефолт `http://localhost:8080`;
  подсказка: «Для сотрудников: адрес компьютера с Квазаром, например
  http://192.168.1.10:8080. Для облака — адрес вида
  https://компания.kvazar.ru»;
- кнопка «Проверить и подключиться» (§5.4): health-зонд → при успехе
  адрес сохраняется в конфиг (§9), окно переходит в состояние загрузки
  интерфейса;
- кнопка «Сохранить без проверки» — для случая «сервер ещё поднимается»
  (владелец ставит оболочку раньше старта стека): адрес сохраняется,
  оболочка показывает экран-заглушку с автоповтором (§6);
- список последних адресов (до 5, этап B) — быстрый выбор для
  сотрудников, работающих с несколькими стендами.

### 5.2 Валидация адреса

- обязателен хост; порт опционален (`:8080`); схема опциональна —
  при отсутствии автоматически добавляется `http://`;
- принимаются ТОЛЬКО схемы `http`/`https`; `file:`, `ftp:`,
  `javascript:`, UNC-пути и прочее — отказ с сообщением «Поддерживаются
  только адреса http(s)»;
- нормализация: обрезка пробелов/конечного слэша; максимум 2000
  символов; сохраняется канонизированный `origin + порт` (без path —
  путь отсекается, интерфейс всегда в корне).

### 5.3 Смена адреса

Из трея/настроек (§7) — тот же экран. Смена адреса меняет origin
вебвю → localStorage сессии прежнего origin не подтягивается:
пользователь логинится заново на новом сервере (ожидаемо и безопасно;
сессии старого сервера остаются в его storage, никаких
перемещений токенов через конфиг).

### 5.4 Проверка достижимости (health-зонд)

Оболочка (Rust, reqwest, таймаут 5 с) выполняет:

1. `GET {server_url}/health` → 200 c `"status":"ok"` — сервер жив;
2. **зонд принадлежности**: `GET {server_url}/api/v1/modules` → 200 и
   JSON-массив с полями `name/version/db_schema` — это именно Квазар
   (защита от «на порту 8080 отвечает кто-то другой» — реальный
   инцидент коробки 2026-10-03: health от соседнего dev-стека дал
   ложноположительный успех). Ответ «жив, но не Квазар» → жёлтое
   предупреждение «По этому адресу отвечает не Квазар» + «Продолжить
   всё равно» (осознанный обход) / «Изменить адрес».

Зонд используется в трёх местах: кнопка «Проверить и подключиться»,
автоповтор экрана-заглушки, фоновый мониторинг (§8.3). Он же закрывает
«поведение при занятом порту здоровья» (О3).

## 6. Состояния оболочки (машина состояний)

```
СТАРТ
  ├─ конфига нет ───────────────► [Первый запуск] (§5.1)
  └─ конфиг есть ──► [Подключаемся] (спиннер, health-зонд,
                       авто-переход при успехе / через 10 с ↓)
                                        │
        ┌───────────────────────────────┤
        ▼                               ▼
[Квазар не запущен]                [Готово: webview с интерфейсом]
  экран-заглушка:                    │  навигация по интерфейсу — фронт ERP
  • адрес + «Изменить»               │  сбой навигации/ответа (сервер упал
  • «Проверить снова» (кнопка)       │  при живом окне) ──────────────┐
  • автоповтор зонда каждые 10 с     │                               │
  └─ зонд ОК ──► [Подключаемся] ◄────┴───────────────────────────────┘
```

Требования к состояниям:

- **[Подключаемся]** показывается немедленно при старте окна (не белый
  экран): логотип-монограмма, «Подключаемся к {адрес}…». Автопереход в
  [Готово] при первом успешном зонде; через 10 с безуспешности — в
  [Не запущен] (автоповтор продолжает работать).
- **[Квазар не запущен]** — дружелюбный локальный экран: «Похоже,
  Квазар на {адрес} сейчас не запущен. Если это ваш компьютер —
  запустите Квазар (Docker Desktop / мини-ПК должен работать). Если вы
  сотрудник — уточните у администратора». Кнопки: «Проверить снова»,
  «Настройки» (смена адреса). Автоповтор зонда каждые 10 с с бэкоффом
  до 60 с при длительном отсутствии (не дёргаем мёртвый хост).
- **Падение сервера при загруженном интерфейсе**: webview сообщает об
  ошибке навигации/запроса — оболочка НЕ роняет окно и не показывает
  сырую ошибку WebView2: показывает [Не запущен] поверх; возврат
  сервера + «Проверить снова» → перезагрузка `server_url`. Уже
  введённые данные фронта теряются как при F5 в браузере (допустимо;
  черновики фронта в localStorage переживают).
- Состояние окна не теряется при сворачивании в трей и возврате.

## 7. Трей, окно, single instance, автозапуск

### 7.1 Главное окно

- Титул «Квазар», иконка QuasarMark (violet), размер по умолчанию
  1280×800, максимизация/ресайз разрешены, минимизация — в панель задач
  (обычное окно).
- User-Agent вебвю дополняется суффиксом `KvazarShell/1.0 (Windows)`:
  экран «Активные сеансы» (`/auth/sessions`) и журналы сервера отличают
  оболочку от браузера без каких-либо правок фронта.
- Загрузка: `{server_url}/?shell=tauri` (признак для точечной адаптации
  фронта, §13).

### 7.2 Трей

Иконка QuasarMark в системном трее; меню (ru):

- «Открыть Квазар» — показать/развернуть окно, фокус;
- «Настройки…» — экран настроек оболочки (адрес, автозапуск, трей,
  уведомления — этап B);
- «Проверить обновления…» (этап B; в v1.1 — открывает страницу релизов
  визитки kvazar-download в системном браузере; встроенный обновитель —
  О1);
- «Выход» — полное завершение процесса (включая свернутое в трей окно).

Левый клик по иконке = «Открыть Квазар». Балун/бейдж трея не делаем
(v1.1).

### 7.3 Закрытие окна → трей (настраиваемо)

- По умолчанию (этап A): закрытие окна = завершение процесса, трей
  уходит вместе с ним. Трей живёт, пока запущен процесс; сворачивание
  окна — обычное, в панель задач.
- Опция «Сворачивать в трей вместо закрытия» (этап B, выключена по
  умолчанию). При первом закрытии окна с выключенной опцией —
  однократный диалог: «Закрыть Квазар или свернуть в трей?» с чекбоксом
  «Запомнить выбор» (паттерн Telegram; спасает и от «приложение
  исчезло», и от «висит невидимое»).
- Реализация: перехват CloseRequested (`prevent_close` + hide), при
  выбранном выходе — реальное завершение.

### 7.4 Одноэкземплярность

tauri-plugin-single-instance: второй запуск `.exe` не создаёт окно/процесс,
а посылает событие первому → главное окно показывается и получает фокус
(даже если было скрыто в трей). Второй экземпляр невозможен в принципе.

### 7.5 Автозапуск с Windows (этап B)

tauri-plugin-autostart (ключ реестра HKCU Run — per-user, без UAC,
согласуется с per-user природой коробки). Опция выключена по умолчанию;
включается в настройках или чекбоксом установщика (этап C). Для
сотрудника автозапуск + восстановленная сессия = «включил ПК — Квазар
открылся».

## 8. Нативные уведомления Windows (инфраструктура + контракт)

### 8.1 Что делаем здесь, что — в серверной спеке

Параллельно пишется спека серверных уведомлений (бэклог H п.2:
персистентность + бизнес-события; её этапы A/B/C). Разделение
ответственности:

- **эта спека (оболочка)** — МЕХАНИЗМ: показать нативный тост Windows,
  клик по тосту → фокус окна; дедупликация; настройки вкл/выкл;
  feature-detect серверного эндпоинта. Гарантируем: когда серверная
  спека даст `GET /api/v1/notifications?unread...` — интеграция сводится
  к маппингу полей заголовок/текст/id (её этапы B/C);
- **серверная спека** — ЧТО уведомлять, право доступа, прочитанность,
  payload, частоту, механику передачи событий в оболочку (О9).

### 8.2 Механизм (этап B)

- tauri-plugin-notification: тост с иконкой Квазара, заголовок =
  заголовок уведомления, тело = текст; клик → `show + focus` главного
  окна (переход на конкретный раздел — deep-link, вне v1.1, О5).
- Дедупликация по `id` уведомления (не показывать повторно в рамках
  сессии оболочки; список показанных — в конфиге-состоянии, §9).
- Feature-detect: механизм включается только если эндпоинт уведомлений
  отвечает (404/501 на сервере старой версии → режим недоступен,
  тишина в UI, повторная попытка раз в час).
- Тестовая кнопка «Показать тестовое уведомление» в настройках
  (приёмка без серверной части).

### 8.3 Polling-контракт (проект, финализирует серверная спека)

- Интервал базовый 60 с (выравнен с текущим клиентским центром,
  `NotificationCenter.vue:183`); при недоступном сервере — бэкофф до
  300 с; при скрытом в трей окне поллинг остаётся (тосты и есть смысл
  фона).
- Разделение по авторизации (инвариант §11 — оболочка не хранит
  токены):
  - Rust-слой оболочки опрашивает только анонимное: health-зонд и
    feature-detect эндпоинта уведомлений;
  - персональные (авторизованные) уведомления опрашивает ВЕБВЮ —
    залогиненный фронт тем же origin с Bearer из localStorage, как это
    сегодня делает центр уведомлений; найденные «новые» события фронт
    передаёт оболочке для показа тоста (механика передачи —
    страница-агент + postMessage на локальный экран-прослойку —
    фиксируется в серверной спеке, О9). Контракт здесь: **оболочка не
    хранит и не передаёт токены; любые авторизованные запросы выполняет
    webview от лица залогиненного пользователя**.
- Гарантия: при выключенных в настройках уведомлениях — никакой фоновой
  активности, кроме health-зонда по требованию экранов.

## 9. Конфигурация оболочки

Файл `%APPDATA%\Kvazar\shell\settings.json` (app_config_dir Tauri;
identifier — `io.github.ilyab56.KvazarShell`, см. О7):

```json
{
  "server_url": "http://192.168.1.10:8080",
  "close_to_tray": false,
  "autostart": false,
  "notifications_enabled": true,
  "recent_addresses": ["http://localhost:8080"],
  "last_shown_notification_ids": ["..."],
  "schema_version": 1
}
```

Правила: только эти нейтральные поля; НИКОГДА — токены, пароли, cookie,
персональные данные (§11); миграция по `schema_version`; при порче
файла — сброс на первый запуск (старый файл переименовывается в `.bak`
для поддержки).

## 10. Сценарии (Given/When/Then)

### Основной

- G: чистая Windows сотрудника, коробка работает на LAN-IP
  192.168.1.10. W: сотрудник ставит оболочку (этап A — скачал
  `kvazar-shell-setup.exe` из релиза визитки; этап C — чекбокс
  kvazar-setup) и запускает. T: экран первого запуска; вводит
  `http://192.168.1.10:8080`; health-зонд зелёный → интерфейс Квазара
  в нативном окне: без адресной строки, иконка Квазара в панели задач;
  логин; далее — обычная работа ERP (весь функционал = браузеру).
- G: владелец на серверном ПК. W: первый запуск оболочки, дефолт
  `http://localhost:8080`, «Проверить и подключиться». T: стек
  поднимается, вход в свою организацию; трей с меню; закрытие окна при
  выключенной опции — процесс завершён (tasklist пуст).
- G: ПК перезагрузили (владелец, автозапуск включён — этап B).
  W: вход в Windows. T: оболочка стартует сама, `restart:
  unless-stopped` стека поднимает сервер, оболочка сама переходит из
  «Подключаемся» в интерфейс ≤ 3 мин (паттерн приёмки коробки п.4).

### Альтернативные

- G: сервер ещё не поднимался (оболочка поставлена раньше стека).
  W: «Сохранить без проверки». T: адрес сохранён; экран «Квазар не
  запущен» с автоповтором; когда стек поднялся — интерфейс открылся
  сам, без действий пользователя.
- G: на порту 8080 отвечает чужой сервис. W: health-зонд: `/health`
  200, но `/api/v1/modules` не похож на Квазар. T: жёлтое
  предупреждение «По этому адресу отвечает не Квазар», выбор
  «Изменить адрес» / «Продолжить всё равно» (осознанный обход).
- G: сотрудник переезжает между стендами. W: смена адреса в настройках.
  T: окно перезагружено на новый origin; токены старого сервера
  остались в localStorage старого origin и не «утекли»; на новом
  сервере — отдельный логин.
- G: предприятие перешло на hub_link-мост (будущее). W: ввод
  `https://компания.kvazar.ru`. T: работа как с любым адресом: никаких
  специальных режимов в оболочке (готовность закрыта конструктивно).

### Ошибочные (обязательные тесты)

- G: интерфейс загружен, администратор остановил стек
  (`docker compose stop`). W: сотрудник кликает по интерфейсу.
  T: оболочка показывает экран «Квазар не запущен» (НЕ белый экран
  webview, НЕ краш, процесс жив, трей жив); «Проверить снова» после
  старта стека возвращает интерфейс; сессия (localStorage) пережила
  перезапуск — без повторного логина.
- G: второй запуск `kvazar-shell.exe` при открытом окне. W: запуск.
  T: новый процесс мгновенно завершается, существующее окно показано и
  в фокусе (в т.ч. если оно было свернуто в трей).
- G: адрес `file:///C:/`, `ftp://x`, произвольный текст без схемы и
  хоста. W: сохранение адреса. T: валидационное сообщение, адрес не
  сохранён.
- G: пользователь залогинен с «запомнить» (токены в localStorage
  webview). W: открыть `%APPDATA%\Kvazar\shell\settings.json` и весь
  каталог конфига. T: токенов/пароля НЕТ (grep по `erp.`/`refresh`);
  они — только в хранилище вебвю-профиля приложения.
- G: конфиг повреждён (не JSON). W: запуск. T: первый запуск с дефолтом
  адреса; старый файл сохранён как `.bak`; сообщения об ошибке нет.
- G: WebView2 Runtime отсутствует (старая Win10 без обновлений).
  W: установка оболочки. T: NSIS-установщик доустанавливает WebView2
  bootstrapper'ом (см. §12.1); при отсутствии интернета — внятное
  сообщение со ссылкой на офлайн-рантайм Microsoft (О6).

## 11. Безопасность

1. **Токены/пароли — вне оболочки**: оболочка их никогда не принимает,
   не хранит, не пересылает. Аутентификация — целиком внутри вебвю
   (вход, 2FA, ротация, «Активные сеансы» — существующий фронт).
   Сессия живёт в localStorage вебвю-профиля origin'а сервера — ровно
   как в браузере (`stores/auth.ts:9-10`). Хранилище вебвю —
   per-app+per-origin, недоступно другим приложениям без профиля.
2. **Конфиг-файл** — только адрес и UI-опции (§9). Проверка приёмки —
   grep по каталогу конфига.
3. **IPC-изоляция**: remote-контент (интерфейс ERP) не получает
   Tauri-API; capabilities описаны только для локальных экранов
   оболочки. Оболочка не внедряет скрипты в remote-контент.
4. **Только http(s) + один адрес**: никакого смешения контента,
   никаких произвольных схем; CSP локальных экранов — строгий
   (`default-src 'self'`), remote-контент живёт под политикой сервера.
5. **Сеть = только health-зонд и (этап B) polling-контракт** к
   единственному `server_url`. Никакой телеметрии, «звонков домой»,
   сторонних доменов в оболочке. Скачивание WebView2 — только
   установщиком и только с CDN Microsoft.
6. **Обновления оболочки** — только по явному действию пользователя
   (§12.4); кодовая подпись артефактов — по готовности сертификата
   (сейчас GHCR/Releases GitHub как источник доверия).
7. LAN-HTTP (без TLS) — осознанный текущий режим коробки
   (`WEB_TLS=0`); оболочка не ухудшает и не улучшает его (трафик тот
   же, что в браузере). Self-signed HTTPS-режим — О4.

## 12. Сборка и дистрибуция

### 12.1 Артефакт

- Крейт `shell/` + статические экраны; сборка `cargo tauri build`
  (CI, rust toolchain stable, без node; tauri-cli через cargo
  binstall).
- Bundle: **NSIS** `.exe` (основной, per-user `installMode:
  currentUser` — без UAC, консистентно с коробкой) + MSI опционально.
  Имя файла: `kvazar-shell-setup-<ver>.exe` (латиница Kvazar).
- WebView2: режим `downloadBootstrapper` (Win11 — рантайм уже есть;
  старые Win10 — докачка ~2 МБ bootstrapper). Офлайн-вариант embed
  (+~127 МБ) — не v1.1 (О6).
- Версионирование оболочки — собственное (`shell 1.0.0` в v1.1
  продукта), не привязано к версии стека: релизы редкие и независимые.

### 12.2 CI

Новая джоба `shell` в `release-images.yml` (по образцу `installer`):
windows-latest → rust-toolchain → `cargo tauri build` → артефакт
`kvazar-shell-setup` → приложение к GitHub Release на тегах `v*` +
копирование ассетом в релиз визитки kvazar-download (операционка из
реестра: curl upload по токену; тело релиза с кириллицей — править в
веб-UI).

### 12.3 Как пользователь получает оболочку

- **Этап A**: отдельное скачивание из релиза визитки
  (github.com/ilyaB56/kvazar-download) — README-инструкция «Приложение
  для Windows» (ссылка + 3 шага: скачать → поставить → ввести адрес).
- **Этап C**: чекбокс «Приложение Квазар для Windows» в
  `kvazar-setup.iss` — файл `kvazar-shell-setup.exe` бандлится в
  установщик коробки ([Files] + [Tasks]), тихая доустановка
  (`/S`, per-user) ПОСЛЕ успешного `WaitForHealth` в том же
  `ssPostInstall`; чекбокс включён по умолчанию для владельца.
  Сотрудникам владелец пересылает файл или ссылку визитки (их машина —
  не сервер; kvazar-setup им не нужен). Идемпотентность: повторная
  установка коробки не дублирует оболочку (проверка ключа Uninstall).
- Обновление установленной коробки (ADR-04, kvazar.cmd) оболочку не
  трогает — они независимы.

### 12.4 Обновление оболочки

Рекомендация v1.1 (О1): пункт трея/настроек «Проверить обновления…» →
открывает страницу релизов визитки в системном браузере; установка —
поверх существующей (конфиг в %APPDATA% сохраняется). Встроенный
tauri-plugin-updater (подписанные minisign-манифесты, автообновление)
— отдельное решение при частых релизах/v1.2.

## 13. Фронтенд: точечные правки (`?shell=tauri`)

Оболочка открывает `{server_url}/?shell=tauri`. Единственная
обязательная правка фронта (этап B, ~5 строк):

1. **Фиксация признака**: при boot, если `route.query.shell ===
   'tauri'` → `sessionStorage.setItem('erp-shell', 'tauri')` (query
   сбрасывается первой же внутренней навигацией, поэтому признак
   фиксируем; sessionStorage переживает перезагрузки страницы в окне).

Кандидаты-правки по признаку (делать ТОЛЬКО при реальной боли, каждая —
отдельным маленьким PR; серверная логика не затрагивается):

2. Скачивания blob (`AssistantView.vue:133`, `ReportsView.vue:147`,
   `ToolsView.vue:252`): в WebView2 работают, но UI загрузок в окне
   по умолчанию невидим — оболочка перехватывает событие загрузки и
   показывает системный «Сохранить как…» (правка ОБОЛОЧКИ, не фронта);
   фронт-правка не планируется. Проверить на приёмке этапа A.
3. Печать сделки (`CrmView.vue:296`, `window.print()`) — диалог
   печати WebView2; проверить на приёмке; при проблеме — кандидат
   «печать через системный браузер» (только по факту проблемы).
4. Тексты про браузер: сегодня кнопок «открыть в браузере»/`window.open`
   во фронте НЕТ (grep) — прятать нечего. Правило на будущее: любой
   новый браузеро-специфичный элемент обязан учитывать
   `sessionStorage['erp-shell']` (скрывать/менять формулировку).
5. User-Agent «Активных сеансов» — решено на стороне оболочки
   (суффикс `KvazarShell/1.0`, §7.1), фронт не трогаем.
6. Центр уведомлений v1-lite остаётся как есть (внутри-приложенческий
   колокольчик); нативные тосты — дополнение, не замена; после
   серверной спеки возможна точечная правка «не дублировать тост для
   уже показанного в центре» (её этапы B/C).

- **Сервер/модули**: НУЛЕВЫЕ изменения кода. Ни новых эндпоинтов, ни

- **Установщик коробки** (`kvazar-setup.iss`): этап C — [Files]/[Tasks]
  + тихий запуск после health; выполняется по чек-листу реестра

- **CI**: +джоба `shell` (rust, windows-latest) и копирование в визитку.
- **RBAC/аудит**: не затрагиваются; UA-суффикс оболочки виден в

- **Документация**: README визитки (раздел «Приложение для Windows»),
  docs/box-readme.md (этап C: чекбокс), раздел поддержки Issues.
- **Новые риски**: (а) поведение WebView2 (загрузки, печать, rate-limit
  nginx — ожидаем обычный клиент как Edge) проверить на приёмке;
  (б) WebView2-рантайм на редких Win10 — bootstrapper (О6);
  (в) два источника установки (визитка/установщик) — версия в «О
  программе» настроек.

## 15. Этапы, объём

- **Этап A — минимальная оболочка (~4–6 дней)**: каркас крейта
  (Tauri 2, окно, loadUrl, UA-суффикс), экраны первого запуска/
  подключения/не-запущен, health-зонд с проверкой принадлежности,
  конфиг + валидация адреса, трей с базовым меню, single-instance,
  иконки/брендинг, джоба CI + артефакт + релиз визитки, blob-скачивания
  и печать проверены в webview. Результат: сотрудник владельца может
  работать в «прямом приложении» уже на этапе A.
- **Этап B — настройки и нативность (~3–5 дней)**: экран настроек
  (адрес, список последних, трей, автозапуск, уведомления),
  автозапуск (плагин), close-to-tray с первым диалогом, нативные тосты
  (плагин + тестовая кнопка + дедупликация + feature-detect),
  polling-заготовка по контракту §8.3, правка фронта §13.1, пункт
  «Проверить обновления…».
- **Этап C — дистрибуция и hub_link-готовность (~2–4 дня)**: чекбокс и
  бандл в kvazar-setup (тихая доустановка после health), E2E чистой
  установки коробки с оболочкой, «О программе» с версией, финальная
  проверка произвольных https-адресов (конструктивная
  hub_link-готовность: адрес — любое http(s); deep-links — О5).
  Итого v1.1: ~2–3 недели одного разработчика (сопоставимо с блоком
  devtools A–C).

## 16. Критерии приёмки (по этапам; вход для QA)

### Этап A

1. Чистая Windows-VM: установка `kvazar-shell-setup.exe` → первый
   запуск показывает экран настройки адреса с дефолтом
   `http://localhost:8080`; ввод LAN-IP живой коробки → окно с
   интерфейсом Квазара; адресной строки нет; иконка Квазара в панели
   задач и в окне.
2. «Убил процесс сервера» (на сервере `docker compose stop`): при
   открытом интерфейсе клик по элементу → экран «Квазар не запущен»,
   процесс оболочки жив (не краш, не белый экран), трей работает;
   `docker compose start` → «Проверить снова» (или автоповтор ≤10 с)
   → интерфейс вернулся; повторный логин НЕ потребовался (localStorage
   пережил).
3. Второй запуск `kvazar-shell.exe` при открытом окне: фокус на
   существующее окно (в т.ч. извлечённое из трея), второй процесс
   завершается (диспетчер: один процесс).
4. Трей: левый клик открывает окно; меню: Открыть/Настройки/Выход;
   «Выход» завершает процесс полностью (трей исчез, tasklist чист) —
   при выключенном close-to-tray закрытие окна равно выходу.
5. Валидация адреса: `file://`, `ftp://`, `javascript:`, «ноутбук
   Васи» → сообщение об ошибке, адрес не сохранён; `192.168.1.10:8080`
   без схемы → автоматически `http://`.
6. Чужой сервис на порту (стенд: любой HTTP-сервер на 8080): зонд
   показывает «отвечает не Квазар»; «Продолжить всё равно» работает
   осознанно.
7. Безопасность: залогиниться с «запомнить» → grep по
   `%APPDATA%\Kvazar\shell\*` (и всему каталогу приложения) не находит
   токенов/пароля; в «Активных сеансах» у сеанса оболочки виден
   UA `KvazarShell/...`.
8. Порча конфига (мусор в settings.json) → первый запуск, `.bak`
   создан, сообщение об ошибке НЕ показывается.
9. Скачивание (экспорт CSV из Таблиц, выгрузка 1C, документ ИИ) и
   печать сделки в окне оболочки работают (файл сохраняется/диалог
   печати открывается); при задержке загрузок — индикация оболочки.
10. CI: джоба shell зелёная, артефакт приложен к релизу; анонимное
    скачивание из визитки работает (проверка браузером в приватном
    режиме).

### Этап B

11. Автозапуск: опция включена → перезагрузка Windows → вход →
    оболочка стартует сама; опция выключена → не стартует.
12. Тост: тестовая кнопка показывает нативное уведомление Windows
    (Focus Assist/режим «не беспокоить» не роняет оболочку — тост
    приходит после снятия режима); клик по тосту → окно в фокусе.
13. Polling-контракт: при отсутствии серверного эндпоинта (текущий
    стек) — тишина, без ошибок в UI и логах; при недоступном сервере
    частота падает (бэкофф), после восстановления — возвращается.
14. Close-to-tray: первый диалог при закрытии; «свернуть в трей»
    запоминается; после этого закрытие скрывает окно, процесс и трей
    живы, «Открыть Квазар» возвращает.
15. Настройки: смена адреса/опций сохраняется между запусками;
    список последних адресов работает; `?shell=tauri` фиксируется
    (sessionStorage) и переживает навигацию по разделам.

### Этап C

16. kvazar-setup с чекбоксом «Приложение Квазар»: чистая VM →
    установка коробки → после health оболочка тихо установлена, ярлык
    есть, первый запуск показывает дефолт localhost; без чекбокса —
    оболочки нет.
17. Повторная установка kvazar-setup поверх (обновление коробки) не
    дублирует оболочку; деинсталляция коробки НЕ удаляет оболочку
    (отдельный продукт) — и наоборот.
18. Произвольный https-адрес (стенд с любым TLS-прокси) принимается и
    работает — конструктивная hub_link-готовность подтверждена.
19. «Проверить обновления…» открывает релизы визитки; версия
    отображается в «О программе» настроек.
20. E2E на чистой VM по чек-листу реестра 2026-10-04 (свежий .exe,
    чистый каталог) — обязателен для финального релиза v1.1.

## 17. Что НЕ входит в v1.1

- Встроенный автообновитель оболочки (tauri-plugin-updater) — О1,
  v1.2 по частоте релизов.
- macOS/Linux-сборки — О8 (Linux — по запросам коробочников на
  мини-ПК; там WebKitGTK, требуется отдельное тестирование фронта).
- Deep links (`kvazar://`) для перехода из тоста в раздел — О5.
- Обновление КОРОБКИ из оболочки (трей «Обновить сервер») — ярлык
  kvazar.cmd уже есть; кандидат v1.2.
- Офлайн-установка WebView2 (embed +127 МБ) — О6.
- Мульти-серверность в одном окне (несколько одновременных серверов/
  вкладок-профилей); один адрес, переключение через настройки.
- Скрытие/замена элементов интерфейса ERP под оболочку, кроме
  перечисленных кандидатов §13 (каждая — по боли, не превентивно).
- Собственный UI внутри оболочки, кроме трёх служебных экранов и
  настроек; любой бизнес-функционал — только во фронте ERP.
- Интеграция с серверными уведомлениями (маппинг событий, право
  доступа, прочитанность) — этапы B/C серверной спеки уведомлений.
- Менеджер загрузок, print-to-PDF, глобальные хоткеи, многооконность.

## 18. Открытые вопросы (с рекомендациями)

- **О1. Обновитель оболочки**: (а) tauri-plugin-updater — автообновление
  с подписанными minisign-манифестами; (б) «Проверить обновления…» →
  браузер на релизы визитки + ручная переустановка. **Рекомендация:
  (б) для v1.1** — оболочка меняется редко, updater добавляет
  ключи/инфраструктуру/инциденты (в т.ч. известные флапы updater на
  Windows); к v1.2 при частых релизах — (а).
- **О2. Поведение закрытия окна по умолчанию**: сворачивать в трей или
  выходить? **Рекомендация: по умолчанию — выход** (предсказуемость),
  первый диалог при закрытии предлагает «свернуть в трей» с запоминанием
  (паттерн Telegram) — компромисс «прямого приложения» и
  прозрачности.
- **О3. Занятый порт здоровья / чужой сервис**: health `{"status":"ok"}`
  может ответить кто угодно (инцидент 2026-10-03 — ложный успех от
  соседнего dev-стека). **Рекомендация: комбинированный зонд** `/health`
  + `/api/v1/modules` с жёлтым предупреждением и осознанным обходом
  (§5.4); строгая блокировка не нужна (обход спасает на нестандартных
  прокси/мостах).
- **О4. Self-signed HTTPS (WEB_TLS=1)**: WebView2 не показывает
  браузерный экран сертификата и блокирует недоверенные. **Рекомендация:
  v1.1 — поддерживаем только доверенные сертификаты; при self-signed
  показываем экран-заглушку с пояснением и гайдом «добавьте сертификат
  в доверенные ОС»; постоянное решение — hub_link-мост с нормальным
  TLS** (план реестра 2026-09-19).
- **О5. Deep links (`kvazar://`)**: клик по тосту → конкретный раздел;
  приглашение «подключиться к серверу» по ссылке (hub_link-онбординг).
  **Рекомендация: не в v1.1**; схему зарезервировать в договорённостях
  брендинга, реализовать вместе с этапом C серверной спеки уведомлений.
- **О6. WebView2 Runtime offline**: bootstrapper требует интернет.
  **Рекомендация: v1.1 — downloadBootstrapper** (Win11 предустановлен);
  embed-вариант — отдельный «offline»-билд по жалобам с закрытых сетей
  (паттерн box-спеки Р1).
- **О7. Идентификатор приложения**: влияет на каталоги конфигов
  (%APPDATA%) и будущие deep links. **Рекомендация:
  `io.github.ilyab56.KvazarShell`** (reverse-DNS от визитки, не
  притязаем на чужой домен); при появлении домена kvazar.ru — менять
  только с миграцией конфига.
- **О8. macOS/Linux — когда?** **Рекомендация: по первому запросу
  коробочного клиента** (Linux-мини-ПК как сервер не означает Linux
  рабочих мест); macOS — с появлением SaaS-профиля. Tauri 2 позволяет
  добавить сборки позже без переделки архитектуры, но фронт придётся
  тестировать в WebKitGTK отдельно.
- **О9. Авторизованный polling уведомлений без хранения токенов**:
  механика «вебвю-агент опрашивает от лица сессии → передаёт в
  оболочку → тост» (§8.3) — единственный способ совместить «оболочка
  не хранит токены» и «тосты видят личные события». **Рекомендация:
  зафиксировать механику в серверной спеке уведомлений** (её этапы
  B/C); до этого оболочка умеет только тестовые тосты; альтернатива
  «анонимные общесерверные тосты (жив/мёртв)» — слабая ценность, не
  делать.
