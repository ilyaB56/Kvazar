# Спецификация каркаса фронтенда (v1)

Каркас веб-интерфейса: три экрана + базовые паттерны, на которых потом
соберётся вся система. Основано на ADR-001 (без CDN), ADR-002 (`/api/v1`),
решении о i18n с первого экрана (группа Б, п. 10).

## Стек

- **Vue 3 + Vite + TypeScript** (Composition API, `<script setup>`).
- **Pinia** (стор: auth, connections), **vue-router** (guard'ы авторизации).
- **UI-библиотека: Element Plus** (таблицы, формы, диалоги, RU-локализация).
  Запасной вариант при проблемах: PrimeVue.
- **vue-i18n** — все строки интерфейса как ключи; v1 только словарь `ru`.
- HTTP-клиент: обёртка над `fetch` (без axios — меньше зависимостей):
  базовый URL `/api/v1`, JSON, Bearer-токен, обработка 401 → refresh →
  повтор запроса → logout при неудаче.

## Размещение и запуск

- Каталог `erp/frontend/` (свой package.json, vite.config.ts).
- **Режим разработки**: `npm run dev` → http://localhost:5173, Vite-прокси
  `/api` → `http://localhost:8000`. CORS на API уже настроен.
- **Прод-режим**: сервис `web` в docker-compose — nginx отдаёт собранный
  бандл и проксирует `/api` на сервис `api` (один origin, CORS не нужен).
  Добавить в compose после готовности каркаса.

## Обязательные правила

1. **Ни одного внешнего запроса**: шрифты, иконки, скрипты — только из
   своего бандла (ADR-001). Проверка приёмки: в Network нет обращений
   к доменам кроме localhost.
2. Все строки UI — через `t('...')` и файлы локали; хардкод текста
   в шаблонах запрещён (i18n с первого экрана).
3. Все деньги в UI — как строки с БД (`'9055.55'`), без parseFloat
   (ADR-003); отображение — фильтром с разделителями.
4. API-клиент типизирован: один файл `src/api/types.ts` с интерфейсами
   DTO (Transaction, Connection, SyncRun...) — единая точка правды о
   контрактах API на фронтенде.
5. Токены: access+refresh в localStorage (v1, локальное приложение);
   logout очищает стор и localStorage. httpOnly-cookie — в будущем
   (задел: весь доступ к токенам только через auth-стор).

## Экраны v1

### Лейаут (после входа)
Сайдбар с разделами: «Подключения», «Синхронизации» (секции будущих
модулей — заглушки «скоро»). Верхняя панель: имя пользователя, выход.

### 1. Логин `/login`
Форма email+пароль → `POST /auth/login`; ошибка 401 — сообщение
«Неверный email или пароль»; успех → редирект на «Подключения».
Гuard: неавторизованный → /login; авторизованный на /login → «Подключения».

### 2. Подключения `/connections`
- Таблица подключений: имя, тип коннектора, статус последней проверки
  (ок/ошибка/—), активность.
- Кнопка «Проверить связь» на строке → `POST .../test` → индикатор
  результата и текст ошибки.
- «Создать подключение» — диалог: выбор типа из `GET /connectors`
  (каталог), поля config рендеруются по `config_schema` типа коннектора
  (string/int/enum → соответствующие поля), поля секретов — `password`
  с маской; сохранение → `POST /connections`.
- Таб «Webhooks»: список (`GET /webhooks`), создание (имя → POST),
  у строки — кнопки «копировать URL» и «токен выдан один раз»
  (токен показывается в диалоге сразу после создания, предупреждение,
  что повторно не показывается).

### 3. Синхронизации `/sync`
- Таблица sync jobs: имя, направление, cron, endpoint, активность.
- Клик по job → панель журнала `GET /sync-runs?sync_job_id=`: статус
  (success/error), items in/out, текст ошибки, время.
- Кнопка «Запустить сейчас» → `POST .../run` → toast «поставлено в
  очередь», журнал обновляется (кнопка обновления + автоповтор раз в 5 с
  в течение 30 с после запуска).

## Приёмка (ручная + smoke-сценарий)

1. `npm run dev`, открыть http://localhost:5173 → редирект на /login.
2. Вход admin@example.com / admin12345 → «Подключения», имя пользователя
   в шапке.
3. Создать подключение http_rest (base_url http://api:8000, health_path
   /health) → появилось в таблице; «Проверить связь» → зелёный статус.
4. Таб Webhooks: создать → URL скопирован, токен показан один раз.
5. «Синхронизации»: запустить smoke-job вручную → в журнале появился
   запуск со статусом success (использовать sync job из smoke-теста).
6. Истечение access-токена (подменить в localStorage на мусор) →
   любой запрос вызывает refresh и продолжается без разлогина;
   мусорный refresh-токен → logout на /login.
7. Выход → редирект на /login, прямое открытие /connections → снова /login.
8. DevTools → Network: ни одного запроса наружу localhost.
9. `npm run build` проходит; собранный бандл открывается через nginx
   (compose-сервис web) и работает против API.

## Non-goals v1

Экраны учёта (транзакции/отчёты), магазин интеграций как каталог карточек,
no-code конструктор рецептов, тёмная тема, роли в UI (кроме скрытия
админ-кнопок), мобильная адаптация (десктоп-first).
